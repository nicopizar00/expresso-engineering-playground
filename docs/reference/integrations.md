# Integration reference

> Status: Reviewed against HEAD 800ac16 by a fresh reader.

This reference records the integration boundaries present in the repository snapshot. Core local development starts PostgreSQL, the BFF, and the OpenTelemetry Collector; the visualizer and observability services are opt-in. Kubernetes, performance, GitOps, and external asset dependencies activate only when their corresponding page, command, or deployment runs.

## Runtime integrations

| -------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web server to BFF                | HTTP through same-origin `/api/bff/*` proxy; server-side requests use HTTP directly | Active when the web application runs. Browser requests use the proxy by default.                                                                                                                                                                                                            | `BFF_INTERNAL_URL` sets the web server destination at build or server start. `NEXT_PUBLIC_API_BASE_URL` can override the client base URL. Defaults target localhost for host development.                          | Proxy requests fail with the upstream HTTP or connection error. The web client surfaces unsuccessful responses as API errors. No retry or timeout is configured in this boundary.                                                                             |
| Web server to visualizer         | HTTP proxy for `/viz` and `/viz/*`; a public URL also opens the standalone page     | The proxy is active when web and visualizer run. The visualizer service is opt-in with the Compose `viz` or `visualizer` profile, or the Kubernetes stack command.                                                                                                                          | `VISUALIZER_INTERNAL_URL` is the server-side proxy destination. `NEXT_PUBLIC_VISUALIZER_URL` supplies the browser-facing standalone link. The standalone link also fails if its host URL is not reachable.                                                                                                                          |
| Visualizer to BFF, REST and SSE  | HTTP GET for the visualization snapshot; Server-Sent Events for live updates        | Active when a visualizer page is opened. SSE is primary. Later poll failures retain the existing scene and report an error. SSE failure starts polling and retries the SSE connection after five seconds.               |
| BFF to PostgreSQL                | PostgreSQL wire protocol over TCP                                                   | Active for BFF persistence. Compose waits for the database health check before starting the BFF. Kubernetes uses a database init container before the application container.                                                                                                                | `DATABASE_URL`; Compose constructs it from the PostgreSQL user, password, database, and service name. Kubernetes supplies the cluster service address and secret-backed credentials.                               | The BFF cannot complete database-backed operations while the database is unavailable. An unreachable collector prevents trace export; application request handling does not depend on trace storage.                                                                                |

| Collector to stdout logs         | Collector debug exporter                                                            | Active whenever the collector receives log telemetry. Collector and application processes continue running.                                                                                                                                   |

Correlation links also require Prometheus data.                                                                                                                                     |
| k6 runner to web and BFF         | Browser HTTP for browser scenarios; HTTP for API scenarios                          | Conditional. Runs only when a performance command or workflow is invoked. Compose HTTP runs default to `http://host.docker.internal:3001`; browser runs default to `http://host.docker.internal:3000`. Kubernetes workflows require the performance platform and their workflow submission. | Performance environment configuration and command arguments provide the target base URL. The Kubernetes workflow templates provide their own target and workload settings.                                         | An unreachable target produces failed requests or checks. ## Activation summary

The default Compose stack starts PostgreSQL, the BFF, and the Collector. The web app, visualizer, and observability stack require explicit profiles or commands. Kubernetes services require their respective cluster setup commands. GitOps, workflow execution, and artifact storage remain dormant until their commands create or submit those resources. Remote browser assets are requested only when the relevant page is rendered.
